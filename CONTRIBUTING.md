# Contributing

This repository follows the [Jaeger contributing guidelines](https://github.com/jaegertracing/jaeger/blob/main/CONTRIBUTING_GUIDELINES.md) and the Jaeger [AI Usage Policy](https://github.com/jaegertracing/jaeger/blob/main/AI_POLICY.md).

## Sign-off

Every commit must carry a sign-off line, which certifies that you agree to the [Developer Certificate of Origin](./DCO):

    Signed-off-by: Your Name <you@example.com>

`git commit -s` adds the line with the name and email from your git configuration. Use your real name.

The DCO check on a pull request fails when any of its commits has no sign-off. To sign the latest commit, run `git commit --amend -s` and force-push the branch. To sign older commits, run `git rebase --signoff main` and force-push the branch.

## License headers

Every new source file starts with the standard header, in the comment syntax of the file:

    Copyright (c) 2026 The Jaeger Authors.
    SPDX-License-Identifier: Apache-2.0

This covers every `.py`, `.sh`, `.yml` and `.yaml` file and the Makefile. The prompt and word-list files (`harness/grader-prompt.txt`, `harness/leak-words.txt`, `harness/system-prompt.txt`, `harness/prompts/*.txt`) carry none on purpose: they are used byte for byte and their sha256 is recorded in every manifest, so a header would change the input.

## Tests

`python3 -B -m unittest discover -s harness/tests` runs the suite offline, with no fixture, no agent and no network beyond localhost; CI runs it on every push and pull request to main. `make lint` checks license headers and line endings and adds a missing header in place, as Jaeger's does, so commit or revert what it changes; CI also runs shellcheck on the shell scripts. `make fmt` also fixes line endings.

`make install-test-tools` then `make test-ci` runs the same suite under coverage and writes `.cover/cover.xml` (use a virtual environment if your Python refuses pip installs). CI runs it and prints the coverage table.

## Experiments, scenarios and records

A run's settings live only in its experiment file (docs/USAGE.md, The experiment file); change one there and say why in its `status`.
Scenario edits, version bumps and CHANGELOG.md lines follow docs/SCENARIOS.md.
Commit the batch records `bench.py run` copies into `records/`, with `records/INDEX.md` regenerated by `bench.py index`.
The inputs of the recorded batches (experiment files, image records, patches, instructions) are under `records/inputs/`; a new experiment starts in `harness/experiments/`.
`stream.jsonl`, `stderr.txt` and the per-cell directories carry session identifiers and stay under `RUNS_DIR`, never in git (.gitignore).

## Goose pin

`IMAGE` in `harness/goose_client.py` and `harness/goose/goose-without-extensions.sh` are copies of Jaeger's `scripts/ai-sidecar/goose`: the image in its `docker-compose.yml` and its wrapper script. A Goose bump means: set `IMAGE` to the demo's new image (tag and digest), copy the wrapper byte for byte, put its sha256 and the Jaeger commit it came from in `test_the_wrapper_is_jaegers_copy` (`harness/tests/test_goose.py`), and re-record the six cases under `harness/tests/data/goose/` (each a `stdout.jsonl` and `goose-stderr.txt` from the new Goose on a stub model). The Goose version and Jaeger commit named in the goose_client.py and test_goose.py docstrings and in docs/USAGE.md change with it.
